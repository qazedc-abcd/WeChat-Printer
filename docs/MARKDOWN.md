# Markdown 识别、检查与打印

## 使用方式

- 在单列文字里输入标题、列表、粗体、链接等 Markdown，编辑器会自动识别并按小票样式预览。点击“保留原文”可以关闭该节点的自动排版。
- 点击“Markdown 排版”新建专用编辑区，或在自动识别提示中点击“打开检查器”。
- 支持导入或拖入 `.md` / `.markdown` / `.txt` 文件，单文件最多 2 MB。
- 本地图片可拖入、批量选择或粘贴截图；完成裁剪后自动上传。点击“复制 Markdown 链接”可把图片插入正文。
- QQ 私聊文字也会自动识别 Markdown，可在消息监听设置中关闭。QQ 的图片打印开关同样控制 Markdown 图片。格式不符合打印限制时，QQ 文本回退到原文排版。

## “符合规范”如何判断

解析器采用随源码附带的 **markdown-it 15.0.3**，以 CommonMark 为基础，启用常用表格等扩展。Markdown 容许很多不完整写法被当作普通文字，因此检查器区分 **格式建议** 与 **实际打印限制**，不会把所有建议都判为语法错误。[CommonMark 规范](https://spec.commonmark.org/0.31.2/)

本地检查自动运行，不需要联网或 AI：

| 提示 | 处理 |
| --- | --- |
| `#标题` 缺空格、标题跳级 | 建议，允许打印 |
| 疑似未闭合粗体、链接、代码围栏 | 建议，允许打印；CommonMark 允许围栏延续到文末 |
| HTML 标签 | 提示按文字显示；不执行 HTML |
| 图片使用相对路径或非 HTTP(S) 地址 | 阻止手动打印，需改为公开直链 |
| 表格超过 16 列 | 阻止手动打印，需拆分 |

本地提示是有限的启发式检查，并非所有 Markdown 风格规则的穷举验证。对于字面量符号、跨行写法等，可能有额外提示；预览和原文切换均保留。

## 小票排版范围

支持标题、段落、粗体、斜体文字、引用、列表、代码块、分隔线、链接、表格与图片。一级标题使用双倍字，其他标题/含粗体的行使用加高字；斜体和代码打印为普通字体。小票接口不能自由更换字体或实现网页的所有样式。

每个 `content` 节点仅写一行，中文按双宽计入 32 单位行宽并折行。表格每行独立一个节点，支持左中右对齐。链接保留目标地址；表格中的图片使用替代文字。原始 HTML 不会执行。

图片必须使用公开 HTTP(S) 直链。发送前由本地服务下载（最多 20 MB）、FFmpeg 白底缩放至 280×280、Floyd–Steinberg 抖动，再上传当前图床，以适配低分辨率热敏打印。编辑时的远程图片预览展示源图，实际黑白处理在发送前完成。

本次未继续探测设备字数或节点上限，现有设备与服务端限制仍然适用。

## 可选 AI 检查（OpenAI 兼容接口）

1. 打开设置中的“Markdown AI 检查”。
2. 启用功能，填写 API 基础地址、接口支持的模型名称及所需 API Key。例如基础地址形状为 `https://api.example.com/v1`。本地接口未鉴权可留空 Key。
3. 点击“保存 AI 设置”。保存时不会调用模型。
4. 在 Markdown 节点点击“AI 检查”。只有该节点的当前正文会发送给配置的接口。
5. 查看摘要、逐条建议和“查看建议全文”；点击“应用 AI 建议”才会替换原文，然后再次检查预览。

接口使用 `POST {baseUrl}/chat/completions`，请求包含 `model`、`messages` 和 `stream:false`，期望 `choices[0].message.content` 返回检查结果 JSON。完整填写以 `/chat/completions` 结尾的地址也可以。为提高兼容性，不要求提供商实现结构化输出专属参数。[Chat Completions 官方参考](https://platform.openai.com/docs/api-reference/chat/create)

默认关闭；自动识别、输入检查、QQ 接收和打印不会自动调用 AI。AI 不会得到设备 SID、图床密钥或 QQ 历史。模型可能给出不合适的修改，建议不会自动应用；原文在请求期间发生变化时，旧建议不能直接应用。

单次 AI 检查最多 60000 字符，超时 60 秒。该限制与设备打印长度没有对应关系。接口失败时仍可使用本地检查和原文打印。
